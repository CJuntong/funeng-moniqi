# 赋能模拟器 · 标准更新流程

更新这个项目时，严格按以下顺序执行（项目根目录：`D:\vibecoding\无畏契约辅助`）：

## 第 0 步：读总纲
- 先读 `Zcode.md`：协作规则、决策记录、进度看板。
- **铁律**：涉及技术选型的新决策，必须列 2~4 个方案（含优劣与推荐）交给用户拍板，不得擅自定。

## 第 1 步：改代码
- 改动最小化，一次只做一个功能点。
- 纯 HTML/CSS/JS 原型（Electron 壳在 `electron/`）；数据在 `data/`；逻辑在 `js/app.js`；样式在 `css/style.css`。

## 第 2 步：语法检查（改动后必做）
```
node --check js/app.js
node --check data/players.js
```
（改了哪个文件就查哪个；新数据文件同理。）

## 第 3 步：浏览器实测
- 本地服务器：`http://localhost:8321`（没开就后台跑 `python -m http.server 8321`，工作目录设为项目根）。
- 用内置浏览器点一遍受影响的界面流程，必要处截图目检。
- 准星渲染比例是用户反复校准过的：**0.625px/代码单位**，不要动。

## 第 4 步：存档（git）
- `git add -A && git commit`，提交信息用通俗中文，说清"改了什么、为什么"。
- 关键节点（一个里程碑完成）加标签：`git tag M<n>`，并在 `Zcode.md` 第九节登记。
- 提交后**钩子会自动验证语法并尝试推送**（见 `.zcode/config.json` 的 PostToolUse 钩子）；推送失败属网络波动，稍后重试：
  ```
  git push
  ```
  （本仓库已固定可用线路；若固定 IP 失效，依次试 `-c http.curloptResolve="github.com:443:20.27.177.113"`、`20.200.245.247`、`140.82.112.3`。）

## 第 5 步：文档同步
- `Zcode.md` 决策记录表追加一行（日期/事项/状态/决定/备注）。
- 进度看板勾选对应里程碑。

## 第 6 步：报告用户
- 说清：改了什么、实测结果、是否已推送 GitHub。
- 提醒：网站 https://cjuntong.github.io/funeng-moniqi/ 会在推送后 1~2 分钟自动更新。

## 已知坑（避免重踩）
- Zcode.md 决策记录**按行追加，不要覆盖旧行**（曾两次误覆盖，均已修复）。
- 后台采集用 general-purpose 子代理，**并发不超过 2 个**。
- 真实人物数据必须有来源，绝不编造；缺失字段写"待核实"。
- GitHub 主站被墙时 api.github.com 与备用 IP 通常仍可用（排障细节见 Zcode.md 决策记录"上传 GitHub"行）。
