# 赋能模拟器 · 开发智能体

用 Agent 工具（general-purpose）调度子代理。**每个子代理的提示词必须自包含**（它看不到我们的对话历史），并遵守以下纪律。

## 全局纪律
1. **并发 ≤ 2**：同时最多 2 个后台子代理，超了会触发用户并发限制直接失败（已有教训）。
2. **绝不编造**：真实人物数据必须有明确来源链接；没有的字段置 null/待核实；预设计类内容（如趣味准星）才可自创。
3. **图片必目检**：采集来的图片要用读图工具逐张确认内容合格（曾有助手交来无关图片）。
4. **文件只放 D 盘**：产物写进项目目录，命名通俗。
5. 子代理完成后：亲自抽查结果再入库，不入库前不算完成。

## 角色一：采集员
用途：批量收集选手/主播/预设准星数据。
提示词模板（发给 general-purpose，可后台）：
```
任务：为"赋能模拟器"采集 <目标> 的数据。
要求：
- 数据字段：<字段列表>；每条必须带来源 URL
- 只收有公开来源的真实数据，编造视为任务失败
- 可用渠道与既往经验：游民星空文章分页、vlr.gg、valorantcrosshairdb.com、valopins.cn、prosettings.net；liquipedia/фandom 基本不可达；github.com 主站被墙时 api.github.com 可用
- 输出：JSON 数组（字段名与 data/players.js 保持一致），附来源清单
- 把结果写入 <指定文件>，不要改动其他文件
```

## 角色二：验证员
用途：发布前全面检查。
提示词模板：
```
任务：验证"赋能模拟器"（D:\vibecoding\无畏契约辅助）当前状态。
检查清单：
1. node --check 全部 js/*.js、data/*.js、electron/*.js
2. 用内置浏览器打开 http://localhost:8321（服务器未开则后台启动 python -m http.server 8321）：
   - 五个导航视图逐一切换（首页/选手库/热门准星/常用准星/娱乐准星）
   - 随机开 2 个详情弹窗：地图预览台放大镜、9 宫格、复制按钮
   - 多人对比：加 2 人 → 开始对比 → 移除
3. 截图 2 张存 D:/tmp/shots/ 并自查
输出：通过项/问题清单（附截图路径）；不要改代码。
```

## 角色三：存档员
用途：按 `.zcode/skills/empower-github-archive/SKILL.md` 的流程执行存档（直接把该文件内容作为子代理提示词的正文）。
注意：存档涉及 git push，**不要并发多个存档员**。

## 典型调度
- 大版本更新 = 采集员（后台）+ 主线程改代码 → 完成后验证员 → 最后存档员。
- 验证员和存档员不并行（存档前要拿到验证结果）。
